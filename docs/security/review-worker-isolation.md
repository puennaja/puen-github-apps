# GOV-003B worker isolation and threat model

**Trust boundaries.** GitHub webhook/PR content, diffs, comments and any changed documents can contain prompt injection. They remain inert data inside `review.v1`; they never select an executable, arguments, work item, authorization reference, environment variable or reporting SHA. Trusted requirements are read from the protected base SHA by GOV-003A, and `AGENTS.md` is required. The private bridge enforces exact SHA and finding grounding again before a Check Run.

**Credential custody.** The GitHub App private key, installation token and webhook secret stay in the reviewer process. The synthetic process receives a clean fixed environment and no `ExtraFiles`. The Go subprocess API closes ordinary non-inheritable descriptors, but this is insufficient proof that every host resource is inaccessible. The worker process must eventually be placed in an independently verified OS/container boundary with no App filesystem, secret mount, credential FD or network route back to the App. No actual provider is enabled today.

**Known gaps.** The private process runner proves bounded I/O, executable allowlisting and timeout/kill behavior only for synthetic fixtures on Linux. It does not enforce the `memory_mib` request field, a network firewall, mount namespace, read-only filesystem, syscall filter, user namespace or per-provider tool policy. Absolute executable allowlisting resolves symlinks but does not protect against on-disk replacement; pin image digest and immutable executable before activation. Model output is untrusted, and schema validation cannot prove semantic correctness. Do not deploy this transport alone as a sandbox.

**Operation allowlist.** Only an advisory Check Run is in the GOV-003A reporter. The worker has no GitHub API operation. GitHub `APPROVE`, merge, push, settings, secrets and Actions/workflow writes remain forbidden. A missing/incomplete/stale review returns `REVIEW_UNAVAILABLE`, and a BLOCKER or MAJOR returns `BLOCKED`. Human Gate Owner `puennaja` alone makes the final approval and merge decision, subject to protected branch rules.

**Activation gate.** Record exact App scopes/repositories/actor, scoped token custody and expiry, isolated worker image and runtime controls, provider CLI version/flags, unattended-use terms, authentication isolation, cost cap, outbound destination policy, no-tool/read-only enforcement, live negative tests and operator rollback before enabling a real adapter. The current App permissions remain Metadata read, Contents read, Pull requests read, Checks write; no expansion is proposed. None of the listed live evidence has been run.

**Rollback and incident response.** Disable webhook processing and review dispatch; drain or quarantine queued jobs; revoke/suspend the App installation if credentials may be exposed; rotate affected secrets; preserve non-secret delivery/job/check IDs and exact SHAs; reconcile any uncertain Check Run writes; do not treat a prior green advisory check as human approval. These are procedures for a future operator, **NOT RUN** here.
