# GOV-001A: `go-githubapp` capability assessment

Assessed 18 October 2026 against the [official project README](https://github.com/palantir/go-githubapp), [selected release v0.48.0](https://github.com/palantir/go-githubapp/releases/tag/v0.48.0), its [module manifest](https://github.com/palantir/go-githubapp/blob/v0.48.0/go.mod), its [tagged client creator source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go), and [GitHub's installation-token API contract](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app). The v0.48.0 source was also inspected in the downloaded Go module cache. No live authentication or GitHub write call was made for this assessment.

## Security-gate finding

**Supported with a narrow integration path; `NewInstallationClient` alone is unsuitable.** `ClientCreator.NewInstallationClient(installationID)` has no repository or permission arguments, and its implementation delegates to `ghinstallation.New` without scope options ([interface, lines 59–80](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go#L59-L80), [constructor, lines 367–382](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go#L367-L382)). GitHub says a token request that omits `repositories`/`repository_ids` and `permissions` receives the installation's full granted repository and permission scope ([token endpoint](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app)). Do not expose or use that default installation client for GOV-001A operations.

The framework does supply an app-authenticated REST client and a static-token REST client (`NewAppClient`, `NewTokenClient`; [tagged source lines 34–89 and 190–278](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go#L34-L89)). Its transitive `go-github/v92` client supports `NewRequest(ctx context.Context, method, urlStr string, body any, opts ...RequestOption) (*http.Request, error)` and `Do(req *http.Request, v any) (*Response, error)` ([tagged client source](https://github.com/google/go-github/blob/v92.0.0/github/github.go#L831-L831), [Do](https://github.com/google/go-github/blob/v92.0.0/github/github.go#L1427-L1427)). Therefore application code can call `POST app/installations/{installation_id}/access_tokens` through `NewAppClient`, with an in-house standard-library JSON body that **always** includes exactly one authorized `repository_id` and an explicit minimal `permissions` map. GitHub documents both scope fields and returns `token`, `expires_at`, `permissions`, `repository_selection`, and `repositories` ([endpoint request and response](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app)). Validate the response's exact repository ID, permissions, selection and expiry before constructing an internal `NewTokenClient(token)`. A missing field, extra repository, extra permission, unknown selection, or short/expired lifetime must fail closed. Keep both clients and token inside an unexported auth/operations adapter; no agent-facing method should return either. This path needs no directly selected `ghinstallation`, `go-githubauth`, or `go-github` module. It remains subject to offline contract tests and later human-authorized live verification.

## Capability map

| Need | Framework evidence | GOV-001A application responsibility |
| --- | --- | --- |
| App JWT authentication | `NewAppClient` builds a REST client using `ghinstallation.NewAppsTransport`; its creator accepts App ID, PEM bytes and base URLs ([source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go)). | Load private key from an approved environment/secret source; validate IDs, URL and key before any network use; do not log credentials. |
| Installation authentication | `NewInstallationClient`/V4 wrap `ghinstallation.New` and refresh installation tokens automatically ([source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go)). | **Do not use these unscoped methods for GOV-001A.** Issue an explicitly scoped token through app client, validate response, then create a private `NewTokenClient`. |
| Repository/permission scoping | No scoping parameters appear in `ClientCreator` installation methods ([source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go)). GitHub token API accepts `repository_ids` and `permissions` ([official API](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app)). | Bind one immutable work item to a numeric repository ID; request exact permission set per operation; compare actual response with request. Do not infer exact scope merely from successful issuance. |
| REST operations | Framework returns the transitive `go-github` REST client, which has generic request/response methods ([framework source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go), [go-github source](https://github.com/google/go-github/blob/v92.0.0/github/github.go)). | Use standard-library request/response structs for repository GET, branch/ref and Git Data writes, draft PR POST, PR GET/PATCH. Enforce operation and field allowlists before sending. Git transport push is a separate implementation concern; no agent-held credential should be used. |
| Webhook verification for future features | `NewEventDispatcher` is an `http.Handler` that calls `github.ValidatePayload` with a configured webhook secret before dispatch ([dispatcher source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/dispatcher.go)); README documents this behavior ([README](https://github.com/palantir/go-githubapp#asynchronous-dispatch)). | Reviewer feature is outside GOV-001A. Keep secret in a secure source; require nonempty secret before enabling webhooks. |
| Offline testing | `ClientCreator` is an interface. `WithTransport` and `WithClientMiddleware` allow HTTP interception; `WithClientTimeout` bounds calls ([client source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go)). | Mock the private high-level adapter. For HTTP tests, inject a round tripper and deny unexpected egress. Note `NewTokenClient` starts from `oauth2.NewClient` rather than `newHTTPClient`, so **`WithTransport` alone does not guard its traffic**; use `WithClientMiddleware` or another central guard. Test scope request and response validation with synthetic data. |
| Credential handling | `Config.SetValuesFromEnv` supports App ID, PEM and webhook secret as environment values; `NewClientCreator` also accepts PEM bytes directly ([config source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/config.go), [client source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go)). | The framework does not provide work-item authorization, safe key custody, scope-response validation, audit records or a restricted agent API. Use in-house standard-library policy/config/audit code; redact errors and avoid raw HTTP request/response logging. |

## Dependency and toolchain facts

The selected release v0.48.0 declares `go 1.27.0`, `toolchain go1.27.1`, and directly requires (among others) `ghinstallation/v2 v2.19.0`, `google/go-github/v92 v92.0.0`, `githubv4`, `zerolog`, `go-metrics`, `oauth2`, caching packages, and YAML; its manifest also lists indirect modules ([v0.48.0 go.mod](https://github.com/palantir/go-githubapp/blob/v0.48.0/go.mod)). These are framework transitive dependencies, not additional integration frameworks selected by GOV-001A. The host's base Go is `go1.22.5`; Go's automatic toolchain selection successfully downloaded `go1.27.2` during this work, making v0.48.0 buildable in this environment. The [release notes](https://github.com/palantir/go-githubapp/releases/tag/v0.48.0) identify the v92 REST client upgrade.

## Remaining security boundaries and gaps

- A scoped token can still write to any branch within its authorized repository if it has Contents write. Branch naming, protected-base restrictions, workflow-path denial, PR ownership, and draft-only rules must be enforced in the application and GitHub rulesets; no `go-githubapp` API applies these policies ([framework client source](https://github.com/palantir/go-githubapp/blob/v0.48.0/githubapp/client_creator.go), [GitHub permission descriptions](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app)).
- A GitHub App token can be scoped by repository and permission, **not by individual branch or work item**. The application's operation boundary and protected-branch rules are necessary additional controls ([GitHub token endpoint](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app)).
- No live permission enforcement, actor identity, App installation selection, or actual token response has been verified. Those remain activation blockers under the existing human gate.
